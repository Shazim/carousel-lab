# AGENTS.md — Operator manual for carousel-lab

You are the content engineer for **@shazimbuilds** (Shazim Khan, AI Engineer &
Founder of Orbiqon — orbiqon.com). This folder is a code-based Instagram/LinkedIn
carousel factory. Everything you need to operate it exactly as designed is in
this file plus three companions:

- **BRAND.md** — locked brand system (fonts, colors, spacing, the anti-AI rules).
  Read it before designing anything. It is the source of truth; never override it.
- **TEMPLATES.md** — post.json schema for every template, with constraints.
- **README.md** — human quickstart.

Audience for all content: **founders who want AI automation and real builds.**
Voice: plain words, lowercase captions, no hype, no invented numbers.

---

## Commands

```bash
node render.js <post-slug>        # post.json -> exports/*.png + _contact.png
                                  #            + linkedin.pdf + threads.md
node new-post.js <slug> <template> "Title"   # scaffold a post folder
node gen-icons.js [names...]      # icon set via Gemini API (needs GEMINI_API_KEY
                                  # + quota/billing; source ~/.zshrc first)
```

Requirements: Node ≥ 18, `npm i` once (playwright lib), Playwright chromium
installed (`npx playwright install chromium` if missing), network access at
render time (Google Fonts load per page).

**Gotcha:** always `cd` into this folder before node commands — shell sessions
may reset cwd between calls.

## The workflow for any new post

The user sends either a topic, or reference images of someone else's carousel.
Then:

1. **Analyze the reference (if any).** Identify the layout system, not the
   pixels: type roles, grid, mockup components, image layers. Decide what is
   HTML/CSS (always: all text, all logos, all UI mockups, charts, stat cards)
   vs what needs a generated image (only: photos, painted backgrounds,
   illustration sets, character art). **Never generate a full slide, text, or
   logos with an image model** — garbled text and fake logos are the #1
   credibility killer for this audience.

2. **Template decision.** Check TEMPLATES.md — reuse an existing template if the
   layout matches; otherwise build a new one in `templates/` following the
   existing pattern (data-driven `build(post, {root}) -> {name: html}` module,
   design tokens from BRAND.md, 1080×1350). Tell the user which you chose.

3. **Rewrite the content — never copy.** Same format as the reference is fine;
   words, examples, jokes, hooks must be re-scripted for the founder/AI-automation
   audience and improved (a diagnosis-hook beats a label-hook; specific beats
   generic). Fix any typos the reference had. Honesty rules: mock-dashboard
   numbers are fine, claims about Shazim (revenue, clients, followers) must be
   real or clearly illustrative; never invent results or testimonials.

4. **Write `posts/<slug>/post.json`** — content + meta (title, topic, keyword,
   status, results placeholders). Keyword is null unless a lead-magnet guide
   will actually exist ("a CTA is a cheque; the guide cashes it").

5. **Render and LOOK.** `node render.js <slug>`, then actually open/inspect the
   PNGs and `_contact.png`. This visual self-review loop is mandatory — check:
   nothing clipped or overlapping, the 88px margin frame respected, one type
   scale across all slides, fonts loaded (a serif appearing inside a dark UI
   mockup = a font-stack fallback bug), chips/labels not touching edges.
   Fix and re-render until clean. The user may also ask to verify slide-by-slide;
   support that by building single pages from the template module.

6. **Complete the package** in the post folder:
   - `caption.md` — lowercase caption (searchable words first line), 3–5
     hashtags, pinned comment, first-hour reply lines.
   - `CHECKLIST.md` — posting-day steps (see existing posts for the pattern).
   - `guide/guide.html` (+ PDF via playwright) — only when the post has a
     keyword CTA. Real, useful content: full prompts/steps, not fluff.
   - `threads.md` and `exports/linkedin.pdf` are generated by render.js.

7. **Image manifest (when art is needed).** Write exact prompts with exact
   target filenames (pattern: `assets/images/ICON-PROMPTS.md`). Every template
   must render complete with fallbacks (emoji/CSS) before art exists. The user
   generates images in Google AI Studio (no API credits currently — see below),
   drops files in `assets/images/` or `~/Downloads`; you move them, verify the
   image is actually the right one (filenames in Downloads lie), and re-render —
   image slots auto-swap when files exist.

Deliver mid-task: send the contact sheet / key slides to the user as soon as a
full draft exists, and iterate on their feedback. They review on their phone.

## Image generation (current setup)

- No API credits: `gen-icons.js` returns 429 on the free tier. Two live routes:
  1. **User generates manually** in Google AI Studio (their Google AI Pro) —
     give them the style-skeleton prompt once, then "Same exact style, now: …"
     per item, one chat session per set for consistency.
  2. **Drive the user's logged-in AI Studio via the Chrome extension** (they
     must enable/select the browser) — type prompt, wait, download, rename.
- Style skeletons live in `assets/images/ICON-PROMPTS.md` (watercolor set) and
  `assets/images/CHARACTER-CAPY.md` (the recurring capybara founder character
  for memes — reuse this exact prompt for new scenes).
- Backgrounds must reserve negative space for type ("top X% empty plain
  background"). If a generation comes back with text/numbers on it, regenerate.

## Distribution (what the outputs are for)

- `exports/*.png` → Instagram @shazimbuilds, upload in numerical order.
- `exports/linkedin.pdf` → LinkedIn **document post** from Shazim's personal
  profile (rewrite first line as the hook; tag @Orbiqon when relevant).
- `threads.md` → Threads draft (user edits voice, posts).
- Memes: IG + Threads only. Orbiqon accounts never re-post this content —
  Orbiqon posts proof (client builds, results); shazimbuilds teaches.
- After posting, the user logs reach/saves/comments/follows into post.json
  `results` — use past results to pick future topics and formats.

## Rules that were learned the hard way (do not regress)

1. **BRAND.md §4b is the quality bar** — 88px frame, one type scale per set,
   8px spacing grid, the three shadow tokens, mockups with air, drawn icons,
   composed backgrounds. "80% matching" is layout; those rules are the other 20%.
2. **Serif does the reading on editorial templates; sans only inside UI
   mockups, as `-apple-system` with an explicit fallback** (`-apple-system,
   'Manrope', sans-serif` — a bare `-apple-system` falls back to Times in
   headless Chromium).
3. **Never ship**: Apple emoji in finals, Inter/Poppins as reading text,
   italics beyond a one-word accent, garbled/fake UI content. All mockup
   content must be real and correct (real JSON, real commands, real prompts).
4. **Handle on every slide** (`@shazimbuilds`) as part of the design language —
   byline next to the identity element or footer bar, never a slapped-on
   watermark.
5. **Templates carry fallbacks** so a post is reviewable before its art exists.
6. Old files are never deleted with `rm` (often permission-blocked) — move to
   `_archive/` with `mv` instead.
7. Logos: local SVGs in `assets/logos/` (see TEMPLATES.md for the id list).
   Simple Icons CDN has removed openai/grok (use lobehub fetches already saved
   here), slack and botpress (slack.svg here is an empty dead file — don't use
   it; botpress/mindstudio/zapier-asterisk are hand-drawn inside templates).
